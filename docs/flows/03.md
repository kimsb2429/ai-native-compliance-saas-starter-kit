# flow 03 · B14 · cross tenant same question

## What you send

I sent the payload from examples/payloads/03-cross-tenant-same-question.json for tenant blueharbor-user.

```json
{
  "agent_ref": "compliance-assistant",
  "prompt": "List the quarterly obligations from the Acme air permit AQ-2024-0117.",
  "stream": false
}
```

## What runs

1. The runtime authenticates the request using a Cognito ID token for blueharbor-user, whose custom:org_id maps to Blue Harbor's org id.
2. The agent resolves to compliance-assistant using the agent_ref, loading its definition from the database.
3. The prompt text references Acme's permit by identifier AQ-2024-0117 and asks for quarterly obligations.
4. The list_obligations tool executes within a database transaction where set_config('app.org_id', <blue harbor>, true) is set.
5. Row Level Security on the obligations table restricts results to rows belonging to Blue Harbor's org id.
6. Blue Harbor has no obligations extracted, so the tool returns 'No obligations found'.
7. The model generates a response based only on that result, with no access to Acme's data.

## What comes back

The agent returned a response stating that the obligations do not cover the requested permit.

```json
{
  "agent_ref": "compliance-assistant",
  "agent_version": 1,
  "prompt_slug": "compliance-assistant-system",
  "prompt_revision": 1,
  "model_id": "us.amazon.nova-pro-v1:0",
  "tools_used": [
    "list_obligations"
  ],
  "stop_reason": "end_turn",
  "text": "The extracted obligations do not cover the quarterly obligations from the Acme air permit AQ-2024-0117.",
  "elapsed_ms": 2518
}
```

The text field shows the model did not reveal any data about Acme's permit. The tools_used array confirms only list_obligations was called, and it returned no results due to RLS. The agent operates strictly within the tenant's org_id context, enforced per transaction in the database.

## What it proves

This flow proves B14: pooled multi-tenancy with tenant isolation via ContextVar and RLS. One agent handles requests for multiple tenants. When a tenant asks about another tenant's permit, the system returns no data, not an error or exposure. Isolation is enforced at the database layer without the agent logic needing to validate tenant ownership.
