# flow 02 · B14 · ask quarterly obligations

## What you send

I sent a request as the tenant Acme Fabrication using the payload file 02-ask-quarterly-obligations.json.

```json
{
  "agent_ref": "compliance-assistant",
  "prompt": "What do we have to do every quarter under our air permit, and who is responsible for malfunction notifications?",
  "stream": false
}
```

## What runs

1. scripts/invoke.py signs in acme-user to Cognito (USER_PASSWORD_AUTH) and gets an ID token whose custom:org_id claim is Acme's org id
2. POST to the runtime invoke URL with Authorization: Bearer <id token>, a new runtime session id, and the payload {agent_ref: compliance-assistant, prompt, stream: false}
3. AgentCore's JWT authorizer validates the token against the Cognito discovery URL and starts a microVM for the session; agent/main.py verifies the token again and sets the tenant ContextVar
4. agent/builder.py loads the compliance-assistant row, resolves prompt slug compliance-assistant-system revision 1 (model: the row's model_size medium = Nova Pro), binds list_obligations and get_document to Acme
5. the model calls list_obligations; agent/db.py opens one pooled connection, runs set_config('app.org_id', <acme>, true), and the RLS policy returns only Acme's obligation rows
6. the model answers from the tool output; the runtime returns one JSON object with prompt_slug, prompt_revision, model_id, tools_used, stop_reason, text, elapsed_ms

## What comes back

The runtime returned a JSON response with the agent’s answer based on Acme's data.

```json
{
  "agent_ref": "compliance-assistant",
  "agent_version": 1,
  "prompt_slug": "compliance-assistant-system",
  "prompt_revision": 1,
  "model_id": "us.amazon.nova-pro-v1:0",
  "tools_used": [
    "list_obligations"
  ],
  "stop_reason": "end_turn",
  "text": "- [Air Quality Operating Permit AQ-2024-0117 §2.1] (quarterly) Conduct a performance (stack) test on Stack S-1 once every calendar quarter, using EPA Method 5, and submit results within 30 days of the test. — responsible: Permittee — due: within 30 days of the test\n- [Air Quality Operating Permit AQ-2024-0117 §5.1] (on-event) Notify the Department by telephone within 24 hours of any malfunction that causes emissions to exceed a limit in Section 1, and in writing within 7 days. — responsible: Permittee — due: within 24 hours by telephone, within 7 days in writing\n- [Air Quality Operating Permit AQ-2024-0117 §5.2] (on-event) The Environmental Manager is the responsible party for all notifications under this section. — responsible: Environmental Manager — due: null",
  "elapsed_ms": 3941
}
```

The `tools_used` field confirms the agent used the `list_obligations` tool. The `text` field includes quarterly and on-event obligations tied to Acme’s permit. The `prompt_revision` and `model_id` fields confirm the agent used the expected prompt and model.

## What it proves

This flow proves B14: the system uses a verified JWT claim to set the tenant context, shares one database connection pool across tenants, and relies on RLS policies to ensure each tenant sees only their own data. No tenant-specific configuration or isolation beyond the ContextVar and RLS is used.
